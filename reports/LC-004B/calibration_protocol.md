# LC-004B frozen protocol

This protocol starts from PR #10 head `1fe04a77a57f57b63c051b98dbde107000c262da`. The commit that first adds this file and the fit manifest freezes the analysis and is recorded by the run. The only model snapshots are the 12 LC-003 warm-up cosine E40 checkpoints for CNN, Shared-1, Shared-2 and Unshared-2 at seeds 42, 123 and 2026. E40 is the primary and sole checkpoint endpoint. Each Shared-2 snapshot also exposes the zero- and one-call prefixes of the same trained head. The result is 18 prespecified checkpoint/call combinations.

## Fit population and objective

The original ShanghaiTech Part A manifest, train270/internal-val30 split and label policy stay fixed. Tertile boundaries are the LC-003 inclusive linear quantiles of training GT heads divided by image area in megapixels. A density equal to a boundary stays in the lower group. Select the first 20 training records in each group when ordered by ascending SHA-256 of compact UTF-8 JSON `["LC-004B",42,dataset,image_id]`. A hash collision breaks by ascending dataset and image ID. All 18 fits use those 60 IDs. The committed [fit manifest](fit_manifest.json) stores image IDs and their selection hashes. The models previously trained on these labels. The fit is an in-sample diagnostic.

The unchanged baseline counts owned candidates with original score strictly above 0.30. Each checkpoint/call combination fits one global cutoff in the inclusive grid 0.05, 0.06, …, 0.95. Minimize the integer sum of absolute per-image count errors, equivalent to MAE across the same 60 images. On ties select the grid point closest to 0.30 in integer hundredths, then the higher threshold. Each fit receives only original train inputs. The queue saves and hashes the complete cutoff table before evaluating any internal-validation image.

## Candidate and metric protocol

Candidate generation uses the archived native-scale tiled inference, raw strict score >0.05 in the existing float32 decode, in-frame coordinates, source tile and midpoint ownership. Count comparisons use the stored original sigmoid score converted to float64 and an exact grid value computed in float64. A stored score exactly equal to a threshold is excluded. Near equality can differ from a rounded display because float32 sigmoid values are discrete. The original 0.05 floor is applied once. The fit cutoff changes only the count mask over that pool.

Count-side local TP/FP/FN use greedy one-to-one matching at δ=0.50 on owned scores above the specified cutoff, with GT-normalized spatial distance and stable ties in candidate order. A higher count cutoff takes a prefix of that candidate ranking and its match assignments. Report predicted and GT heads, MAE, RMSE, precision, recall, per-image changes and the same train density groups on internal validation.

Local nAP pools stable original score ranks from every in-frame candidate above the original floor. The count calibration uses the same candidates, GT associations and rank AP. The equivalent monotonic odds multiplier maps the fit cutoff to 0.30 for an invariance check only. It leaves the primary count comparison in the original score space and applies no second score floor. Check for changed stable rank positions and newly tied distinct scores in float64. If ranks agree, recompute rank AP using the mapped scores and the same matches. Scores equal before the transformation preserve their original stable tie order. The two separately labeled floor diagnostics retain original scores >0.10 and >0.20 from the same pool, so any AP differences there describe a candidate-selection change.

The per-image candidate digest includes compact sorted JSON for source tile geometry, canonical array shape and dtype, original score and coordinate bytes as little-endian float64, tile IDs as little-endian int64 and ownership flags as bytes. Population digests hash the ordered image IDs and candidate digests. The fit and validation ID hashes, original data manifest SHA-256, cache weight digest and each checkpoint/config digest are archived.

## E40 comparison and decision

For each seed compare independently trained full-depth Shared-2 against separately fitted Shared-1 and Unshared-2, retaining the frozen 0.30 comparison. Use exact sums of absolute error divided by 30 before calculating differences. Per-seed closure is (raw gap − fitted gap) / raw gap when the raw gap is positive, and N/A otherwise. Report absolute gaps for every seed. The primary mean closure is the same ratio applied to the arithmetic mean raw and fitted gaps across all three seeds. For each comparator, declare a calibratable component under this diagnostic only if mean closure is at least 50%, at least two seeds with positive raw gaps narrow their gaps, and fixed-pool rank orders and local nAP remain invariant in the compared arms. Both comparator checks must pass for an overall positive decision.

Prefix comparisons pair images of the same E40 checkpoint and also show all separately trained controls. The head was trained on full-depth features. Intermediate features can have a different distribution. Prefix results inform the error analysis and do not establish an independently trained architecture comparison. Any inference about a calibratable component is exploratory and limited to this split and training procedure. This task fits thresholds only, uses internal validation once per frozen case, runs no model training and leaves the official test split out of the workflow.
