# LoopCrowd data and evaluation protocol

## Label and split policy

ShanghaiTech A/B use the LC-001 author archive and zero-based original pixel coordinates. Each raw MAT count is reconciled against its point array. The strict converter rejects any non-finite or out-of-image coordinate. The pilot uses the explicit LC-001 out-of-bounds rejection option, which removes finite points outside the decoded image bounds and writes their original indices and coordinates to a local log. All retained points stay in input order and keep their coordinates. Coincident ground-truth points remain separate annotations. Part A contains 270 train and 30 internal validation images, and B contains 360 and 40. The SHA-256 rank with seed 42 selects internal validation exclusively from the official training set. The official test split is reserved for a frozen final checkpoint and protocol. Train and validation runs never load its image pixels or use its annotations for metrics.

NWPU-Crowd uses the LC-001 released format, official train/val IDs, zero-based native coordinates and hidden test annotations. Run strict conversion first once the original images are available. If needed, use `--out-of-bounds-rejections` and reconcile each split's original point count against retained and excluded points. Run the full-frame and crop audit with `scripts/audit_dataset.py`, once with `--split train` and again with `--split val`. Real NWPU F1 is `not_ready` until the original box-based official evaluator is wired and verified. [NWPU benchmark and evaluator](https://github.com/gjy3035/NWPU-Crowd-Sample-Code-for-Localization)

## Crop and overflow audit

Use `scripts/audit_crops.py --manifest <A.jsonl> --manifest <B.jsonl> --output <report.json>`. It evaluates one 512 × 512 crop per image for seeds 42, 123 and 2026 on train and internal validation. The uniform origin is sampled on the valid integer lattice with a per-image RNG derived from seed, dataset, image ID and epoch. Density-biased crops add three seeded, jittered proposals around sampled points and keep the candidate with the most in-crop points, with ties favoring the earlier candidate. An axis shorter than the crop is padded at the bottom or right. Point intervals are half-open. Full per-image counts are written by default. `--aggregate-only` drops image identifiers. Pooled loss is `Σ max(0, n_cell - K) / Σ n_cell` with a null rate when there are zero points. Reports distinguish crop-retained points from source points.

Training uses the configured, epoch-seeded native-resolution crops and the same ImageNet RGB normalization across variants. Stride 4 and K=2 are pilot parameters. Within each grid cell sort by `(x,y)`, assign up to K targets, and count every extra point in the epoch's `overflow_gt`. The point classifier trains only on valid grid cells. Offsets train only on assigned positives. An enabled density head sees all in-crop points, including overflow. The default density weight is zero for every pilot variant. Validation compares against every retained full-image label, including points unreachable under the training slot limit.

## Full-image prediction

Evaluation uses batch-one tiles of size 512 with 128 px nominal overlap at native scale. Tile starts include the final possible origin. Input padding is normalized zero. Decode logits and within-cell offsets in native coordinates using `x=left+4*(col+dx)` and `y=top+4*(row+dy)`. For each point above the score floor, remove padded/out-of-frame coordinates and attach the source tile ID. Exported tile metadata includes its valid image box and its half-open ownership rectangle. The rectangles meet at midpoints of adjacent tile overlaps.

- **Point AP/nAP** consumes all in-frame candidates above the configured score floor (0.05 in the LC-002R runs). Tile ownership and distance suppression leave this candidate stream intact. The one-to-one matcher labels unmatched duplicates as false positives.
- **Counting** consumes only candidates in their source tile's ownership rectangle, then applies the score threshold (0.30 for checkpoint selection). Identical coordinates produced by multiple overlapping tiles have one owner. Distinct nearby coordinates survive, including across a seam. No radius suppression is applied. Shifted duplicate predictions can survive on opposite sides of a seam. Two owned, above-threshold points from overlapping tiles within 2 px are recorded as an ambiguous pair and retained. The count of exclusions by ownership is recorded separately and cannot identify missed GT heads. The number of distance-based reconciliations is always zero.

LC-002 at `544c480` used a different candidate protocol. Its historical metrics and checkpoints retain that revision. LC-002R applies the corrected protocol on every new validation call. Results from the two evaluation protocols should be kept with their respective code revisions.

## Score calibration

Per-epoch MAE and RMSE use the fixed count score cutoff and all cleaned full-image labels. The count sweep uses `--threshold-sweep` in `scripts/evaluate.py` on internal validation only. After training, reload the lowest fixed-threshold validation MAE checkpoint (earliest on ties) and sweep strict score thresholds 0.05 through 0.95 in increments of 0.05. Compute per-image MAE/RMSE, pooled predicted and GT heads, and micro precision/recall from the same count candidates using the local one-to-one rule at δ=0.50. Precision is null when there are zero predictions and recall is null when there are zero GT. The minimum internal-validation MAE selects the score cutoff. Break ties by RMSE, distance to 0.30, then lower cutoff. This result is calibrated and checked on the same validation images. Local nAP retains its original score floor for the entire sweep.

The evaluator checks that the input manifest SHA-256 matches the checkpoint. Official test evaluation requires `--split test --frozen-test`, and score sweeps are prohibited on test. The JSON predictions export works on unlabeled images, where count and local nAP metrics remain unset.

## Local point metric and parity

`nap_local_v1` uses ten distance tolerances from 0.05 to 0.50. Normalize Euclidean distance by the GT's mean distance to its three nearest other labels. With two or three GT points use all available neighbors. With one use 1 px. Floor zero neighbor means at `1e-12` to admit exact duplicate coordinates. Process predictions by descending score. For a prediction, choose the nearest normalized-distance, as-yet-unmatched GT in the same image when the ratio is strictly below δ. Ties use image and original candidate order, with GT index breaking equal-distance matches. AP integrates the all-points precision envelope against recall increments. Empty reference sets yield null AP. Fix the score floor when comparing runs.
